# Categories and reports

Compiled digests synthesized from captures under `~/.tweetmd/out` — e.g. "compile
saved tweets on a topic" — one Markdown file per topic, generated by
`scripts/generate-report.ts` rather than hand-formatted, so every report has
the same shape (frontmatter, dek, themed body, sources list).

Generated reports are local output and are ignored by Git. Review them for
private content before sharing. Only this maintenance guide belongs in the
repository.

Captures are grouped by topic in `~/.tweetmd/out/categories.md`, generated
from the manifest at `~/.tweetmd/out/categories.json` — read a category's
bundles to compile a report from. Every capture is categorized automatically
(`src/categorize.ts`, wired into the capture pipeline): a `claude -p` call
classifies the author’s thread and bounded excerpts of fetched linked sources
against the existing hierarchy, proposing a new
category/subcategory when nothing existing fits. Proposed topics and low-confidence
answers are marked for review rather than silently expanding the hierarchy. Each
assignment records model/manual provenance, prompt and taxonomy versions, a short
rationale, confidence and review status. `categories.md` is
regenerated on the spot. Pass `--no-categorize` to skip this during capture,
or `--category <id>[/<sub>]` to file it under a category you choose (created
if it doesn't exist yet) without the `claude -p` call.

`npm run categorize` is only needed for a manual re-render (e.g. after
hand-editing `categories.json`) or to audit for stale/uncategorized entries:

```bash
npm run categorize
# Explicitly accept/correct a topic proposal:
npm run categorize -- --bundle example --category search/ranking
# Independent collections and secondary tags (comma-separated; empty clears):
npm run categorize -- --bundle example --collections reading-list --tags retrieval,reranking
# Migrate a legacy category that was really a collection (does not infer topics):
npm run categorize -- --move-to-collection reading-list
xmd prompt collection/reading-list
xmd prompt tag/retrieval
```

Collections and tags never replace the primary topic. Existing manifests remain
readable without migration; moving a legacy category to a collection is explicit
and marks its members as needing a primary topic. Existing `xmd prompt reading-list`
references continue resolving after migration. Category updates use a cross-process
writer lock and atomic replacement; malformed manifests are reported, never reset
silently.

Generate one:

```bash
npm run report -- --config <path-to-config.json>
```

Config shape:

```json
{
  "slug": "topic-slug",
  "title": "Report Title",
  "dek": "One or two sentences describing the report.",
  "compiledAt": "YYYY-MM-DD",
  "body": "## Section\n\nMarkdown body, already written out.",
  "sources": [
    { "handle": "someuser", "date": "YYYY-MM-DD", "url": "https://x.com/someuser/status/...", "note": "short description" }
  ]
}
```

The generator only owns the consistent shape (frontmatter, sources footer) —
the actual research/synthesis is done by whoever is compiling the report.
